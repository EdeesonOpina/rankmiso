# Content readiness (M11.5, unreleased)

Where: report and sidebar → Site intelligence → **Discoverability** → **Content readiness** tab.

It runs on the page snapshot RankMiso already collected for the current analysis. It makes no network request, asks for no permission, and saves nothing. The Rust engine (`seo-rules::readiness`, WASM `analyze_readiness`, input schema 1) groups existing page checks by id and adds the rules below. All findings have weight 0; the page score does not change.

Google states that AI Overviews and AI Mode have no additional requirements, need no special files or schema, and that optimizing for them is still SEO. So these are page-quality observations relevant to search and AI-assisted search, not AI requirements, and nothing here predicts whether any service will show or cite the page.

## Statuses

| Shown             | Engine status                 | Meaning                                               |
| ----------------- | ----------------------------- | ----------------------------------------------------- |
| Review            | WARNING / ERROR               | A concrete defect or contradiction was observed.      |
| Opportunity       | INFO with a recommendation    | Something worth a human look; often fine.             |
| Observation       | INFO without a recommendation | Shown for reference only (for example word count).    |
| No issue observed | PASS                          | Checked, nothing found.                               |
| Not measured      | UNAVAILABLE                   | The data needed is missing; never counted as passing. |
| Not applicable    | NOT_APPLICABLE                | Not expected for this page or page type.              |

Summary counts: checks completed (everything measured and applicable), opportunities (Review plus Opportunity), not measured, not applicable. No score.

## Page type

`article` when JSON-LD has an Article type (Article, NewsArticle, BlogPosting, TechArticle, ScholarlyArticle, Report, LiveBlogPosting), `og:type` is `article`, or `article:published_time` exists. `product` for Product JSON-LD or `og:type=product`. Otherwise `general page`. Author and date expectations apply only to articles.

## Limits

- Consistency checks read JSON-LD only. Microdata and RDFa are counted elsewhere but not compared here.
- Visible bylines, visible dates, text inside images, and content behind clicks are not read. A missing machine-readable author is an opportunity, not proof that no byline exists.
- Element paths are at most six levels deep, so the main-region check can be "Not measured" on deeply nested layouts.
- Crawler access and HTML comparison results live in memory for the open report page. A full reload clears them; readiness then shows "Not measured" again. A result older than the latest page analysis is labelled as such.
- llms.txt is not checked (see `docs/development/m11-plan.md`).
- Firefox: readiness itself needs no network and uses the same code, but it has not been run in a Firefox runtime. The HTML comparison it can draw on is file-only in Firefox.
