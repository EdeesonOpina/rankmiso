## Source-verified crawl limits and corrections

The shared source defines 100 pages, depth 3, concurrency 2, a 10-second request timeout, a 1,000,000-byte page-body limit, five followed redirects, a 120-second total crawl deadline, 400 discovered URLs, and one retry for 429/503 responses. The deadline starts before robots/sitemap preflight and aborts the request signal. Robots fetching uses the same 10-second deadline and five-redirect bound; it previously lacked both. Stop during the 500 ms retry delay no longer dispatches a retry. Literal IPv6 link-local/ULA/multicast, IPv4-mapped private IPv6, and invalid IPv4 values received focused classification coverage. Focused crawler suite: 16 passed, 1 opt-in skipped.

## Security assessment and release blockers

Firefox basic crawling was confirmed by the product owner. That does not establish every network safety property. The extension validates URL origins and literal address classes before fetch/redirects, but browser WebExtension fetch APIs do not expose a portable resolve-and-pin operation. A DNS preflight would still race the actual connection. Firefox `dns.resolve()` needs an additional API permission and returns an asynchronous DNS result; it cannot bind that result to the later fetch. Chrome's `webRequestBlocking` is unavailable to ordinary MV3 extensions, and an observer cannot pin the fetch connection. Chrome Local Network Access behavior is browser-controlled and was not established for this extension-origin fetch. The exposure requires a crawl to a hostname whose answers change between same-origin requests so that one resolves to a local/private destination. Same-origin checks, literal-address blocking, browser policies, user-initiated scope, and crawl budgets reduce exposure but do not prove prevention. Treat DNS-rebinding/private-network reachability as an **unresolved release security blocker**; do not claim a preflight fix.

The least-invasive safe resolution is to obtain browser/runtime security review and demonstrate that installed supported browsers block the relevant extension-origin requests before allowing submission. If they do not, the safe product alternative is to disable remote Site Explorer crawling in affected builds until a browser-supported pre-connection enforcement mechanism is available; a backend proxy, native host, or broad new permission is not introduced in this milestone. Native request-log verification of redirects, denial/revocation, cancellation, robots exclusions, and limits remains outstanding.

The public Privacy Policy Version 6 page was reviewed. It identifies v0.3.0 as current, labels v0.4.0 capabilities as upcoming, and still describes Site Explorer crawling as Chrome-only. Before submission, the policy must be updated to reflect implemented Firefox user-initiated, selected-origin crawling, while retaining caveats for unverified safety behavior and Firefox's excluded network features. The website repository was not modified.

## Decision

The Chrome and Firefox v0.4.0 ZIPs and the Firefox source ZIP were rebuilt from the isolated candidate after G1 corrections. All three archives pass ZIP integrity checks; SHA-256 verification passes. The Firefox source archive was extracted and rebuilt in an isolated directory; the resulting 24-file Firefox package is byte-for-byte identical to the candidate package. Playwright reports 10/10 passing. The artifacts are suitable for internal review, but **store submission is not ready** until the DNS-rebinding/security boundary is resolved or safely constrained, outstanding native security scenarios are verified, Chrome runtime regression is completed, and public policy/store disclosures are aligned. No publication action was performed.
