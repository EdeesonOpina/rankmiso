# v0.5.0 privacy disclosure proposal

**Status: review draft only.** This proposal is for release and store-listing review. It has not been published to the Miso Ecosystem website or submitted to either browser store.

## User-facing disclosure

RankMiso analyzes the page open in your browser. The optional local MCP companion adds Native Messaging so RankMiso can save an audit you explicitly share to a private folder on your device. RankMiso does not automatically share audits, require an account, upload audits to Miso servers, or collect MCP telemetry.

When you confirm **Share with MCP**, RankMiso sends the audit, including the page address and title, to the companion on your device. Shared snapshots remain in local per-user storage until you remove them or delete the files. Uninstalling the companion removes its executables and browser registrations but preserves snapshots and client configuration.

Codex or Claude Code can read snapshots through the five read-only RankMiso MCP tools. Your selected AI client may send retrieved audit content to its model provider according to that client's settings and privacy terms. Local RankMiso storage does not mean AI processing stays local. Removing a snapshot prevents future retrieval from RankMiso's folder, but cannot retract content already received by an AI client or provider.

## Chrome Web Store checklist

- Declare Native Messaging as optional and explain that it connects RankMiso to a separately installed local companion for user-approved audit sharing and management.
- Disclose that the audit may include website content such as page text, links, metadata, and structured data, plus the page URL and title.
- Explain that sharing starts only after the user confirms the Share with MCP dialog, and that the destination is the local companion.
- Explain the separate possibility of AI-provider processing after the user configures and invokes an MCP client.
- Keep the listing, privacy policy, permission justifications, and in-product disclosure consistent. Review the current [Chrome Web Store privacy disclosure guidance](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy) and [prominent disclosure requirements](https://developer.chrome.com/docs/webstore/program-policies/disclosure-requirements) before submission.

## Firefox Add-ons checklist

- Keep `data_collection_permissions.required` as `["none"]`.
- Declare optional `browsingActivity` and `websiteContent` categories because shared audits include page addresses and website content.
- Request those categories through Firefox's user-initiated data-consent prompt before audit sharing or reading saved audit metadata. Native Messaging remains a separate optional permission request.
- Explain that permission is optional, sharing is user initiated, and snapshots are stored locally. Review Mozilla's current [built-in data consent guidance](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/) and [Add-on policies](https://extensionworkshop.com/documentation/publish/add-on-policies/) before submission.
