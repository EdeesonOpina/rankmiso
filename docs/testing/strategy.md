# Testing strategy

Rust unit tests cover missing titles, alt text, noindex wording, canonicals, heading order, CJK word counts, English stop words, JSON-LD errors, schema rejection, truncation, link classification, HTTP warnings, and score exclusion.

Vitest covers CSV formula prefixing, HTML escaping, DOM extraction, highlight cleanup, status badge text, popup summaries, link groups, share cards, readable JSON-LD including graphs and the depth bound, thousands separators, PageSpeed response parsing, report comparison storage, legacy history records, score comparability, finding deltas, history export escaping, optional site-probe behavior, sitemap discovery, XML extraction, limits, cancellation, and CSV export, and the site crawl queue, scope, robots failure, cancellation, one retry, duplicate metadata, and CSV export.

Playwright loads the built Chromium extension and verifies that its popup renders, that a scored fixture audit works, that the report and sidebar navigation reach the same sections, that the sitemap explorer reads local sitemap fixtures, that Site Explorer crawls one local host, skips a disallowed path, stops, opens a page, and exports CSV, that History saves real audits, keeps them after reload, separates two pages, and labels a legacy save as not comparable, and that Technical compares fetched HTML with a script-updated title and canonical and shows Microdata and RDFa counts. It also checks the Firefox package id and bundled WASM asset. Build both with `pnpm --filter @rankmiso/extension build` and `pnpm --filter @rankmiso/extension build:firefox`, then run `pnpm --filter @rankmiso/extension test:browser`; install the Playwright Chromium runtime with `pnpm --filter @rankmiso/extension exec playwright install chromium` first. The Chromium test uses the regular browser channel because Playwright's headless-shell binary does not load extensions reliably. Firefox's published behavior still needs manual verification.

Not automated yet:

- Extension load in Firefox and Edge
- SPA history changes
- Keyboard walkthrough of the dashboard
- Performance benchmarks across supported browsers
- INP capture lifecycle and Event Timing interaction aggregation in a real browser; verify these manually with `docs/testing/manual-checklist.md`

Prefer fixtures over live sites. The extractor test builds its own document.

## Visual checks for UI milestones

Automated tests do not approve a visual design. A UI milestone needs rendered screenshots of the popup, the sidebar near 350px, and the full report, in light and dark, on scored fixtures rather than an extension-blocked page. Review the images for wrapped tabs, horizontal page overflow, overlapping controls, hidden primary destinations, and unreadable text. Continuation screenshots for UX-9 live in `docs/design/reviews/ux9-continuation/` and are not part of the extension package. The light canvas is white. Meaningful groups use a white card with a neutral border, not a coral outline. Miso red is limited to the active destination and the primary action. Headings should read as an outline inside that card. Links at sidebar width should wrap instead of clipping the URL. Social previews should show an Open Graph attachment and a distinct X card, with a short line when the image is missing, and a gap between the preview, Full values, and the notes. Schema should show a collapsible property tree and a raw JSON view. Links should open by group, with nofollow, sponsored, and ugc on the row. The tab strip should show a scroll meter and a hint when tabs overflow, and no fade on a side that has no more tabs. Record the viewports that were actually opened. Playwright currently covers 320, 350, 360×640, 420×650, 420×720, 768×1024, and 1280×800 on the scored audit. The popup tab strip is also dragged with the mouse: the strip must scroll, and that drag must not select another tab. Product-owner approval stays separate from a passing test run. UX-9R replaced the popup tab strip with a vertical rail, so the drag-the-tab-strip check applies to the earlier shell. UX-9R.2 screenshots of all 18 popup destinations, plus a dark Issues shot, are in `docs/design/reviews/ux9r2/`. The HTML prototypes are screenshotted beside them. Those images are not in the extension package.
